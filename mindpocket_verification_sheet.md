## Recording rules

Statuses: NOT RUN, PASS, FAIL, BLOCKED, N/A. Every row begins NOT RUN. PASS requires an observed result and evidence. Use BLOCKED when tools, devices, credentials or implementations are missing. N/A needs a scope reason; it must not hide an unfinished promised feature.

Priorities: P0 = data loss, privacy or security blocker; P1 = essential correctness; P2 = polish. Optional semantic/cloud cases can be N/A only for a release that explicitly excludes those features.

Use synthetic fixtures: clear screenshot with known text, no-text image, blurry/corrupt image, duplicate image, short and long spoken recordings with reference transcripts, silence/noisy recording, linked OneChurch sample memories, and unrelated distractor memories. Do not use real private data for adversarial tests.

> Note on the fixtures actually used. The device's own screenshot folder was imported (3 items) by the app's first-run pass, which is the behaviour under test; those are device screenshots, not authored fixtures. The authored fixtures were `ocr_sample.png` (known text: "OneChurch App", "Dashboard", "Giving", "Sermons", "Events") and a deliberately text-free black screenshot. No audio fixture with a reference transcript existed in the workspace, so transcription accuracy is unmeasured rather than guessed.

## End-to-end acceptance run
